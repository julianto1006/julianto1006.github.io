The Effect of Physical Activity on Sleep Quality

Analyzed data from 452 individuals ages ranging from 9-69 to explore whether exercise frequency affects sleep quality. Found that working out more often leads to better sleep efficiency and deeper sleep, but surprisingly does not have much effect on REM sleep. Results suggest that regular physical activity is a meaningful contributor to overall sleep quality.

Python pandas matplotlib seaborn Jupyter Notebooks
More details

Problem

Getting quality sleep is harder than it seems. With busy schedules, varying activity levels, and countless factors affecting rest, it can be difficult to know what actually makes a difference. Many people struggle with poor sleep without understanding the role that physical activity plays a challenge that affects energy, focus, and overall health across all age groups.

Approach

Sourced a sleep and exercise dataset from Kaggle containing 452 individuals ages ranging from 9–69. Features included sleep duration, sleep efficiency, REM sleep percentage, deep sleep percentage, light sleep percentage, number of awakenings, and exercise frequency. Used histograms to explore the distribution of each variable, scatter plots to compare exercise frequency against each sleep metric, and a correlation heatmap to identify which factors had the strongest relationship with one another.

Results & Impact

Analysis revealed that higher exercise frequency was associated with greater sleep efficiency and deeper sleep, while reducing the number of nightly awakenings. Light sleep percentage decreased as exercise frequency increased, suggesting a shift toward more quality sleep stages. REM sleep percentage remained largely unaffected by exercise frequency. Overall, the findings support that regular physical activity is a meaningful contributor to better sleep quality.

Regional Sales Analysis

Analyzed January sales transactions across four U.S. regions and three product categories to identify which segments drive the most revenue and unit volume. Outputs a summary CSV and bar charts and runs in Docker so anyone can reproduce the results without touching their own Python environment.

Python pandas Matplotlib Numpy Jupyter Notebooks Docker VS code venv conda
More details

Problem

Raw sales data alone does not reveal which regions or product categories are performing best. Without a structured analysis, business decisions around inventory and resource allocation are based on guesswork rather than evidence.

Approach

Combined January sales transactions with a customer lookup table to summarize revenue and units sold by region and product category. Generated two bar charts and a summary CSV saved to the outputs folder. The full pipeline was containerized using Docker for reproducibility.

Results & Impact

The Northeast generated the highest total revenue while hardware was the top performing category by units sold across most regions. The category unit volume chart revealed that high unit count does not always correspond to high revenue, adding a perspective the original revenue plot alone could not show. The full pipeline can be reproduced with a single Docker command with no local environment setup required.

NYC 311 Service Request Resolution Prediction

Analyzed NYC 311 service requests to understand response times and built a simple model to predict whether a request will be resolved within 3 days. Outputs summary data and model results, and runs in a structured notebook workflow.

Python pandas Matplotlib Numpy Jupyter Notebooks SQL AWS S3 AWS Athena AWS SageMaker
More details

Problem

Raw 311 service request data doesn't clearly show which requests are resolved quickly and which are delayed. Without this insight it's harder to prioritize requests and assign city resources efficiently.

Approach

Queried and cleaned 311 service request data using AWS Athena. Created a target variable for resolution within 3 days and engineered features such as complaint type, agency, borough, and time of submission. Trained a binary classifier using SageMaker's Linear Learner algorithm and evaluated its performance to distinguish fast vs. slow resolutions.

Results & Impact

The analysis showed that resolution time varies by complaint type, agency, and time of submission. The model was able to identify patterns in faster and slower requests providing a simple way to flag requests that may take longer to resolve. This can help guide better prioritization of incoming service requests.
